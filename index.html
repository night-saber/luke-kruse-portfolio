    The long way

    I learned to code the hard way — and that's the point

    When I started in elementary school, there was no chatbot to ask and no AI to autocomplete the answer. You found the bug by reading your own code until you spotted it. You learned a function by using it. You built a game because nothing was going to build it for you.

    That's the foundation everything since stands on. When AI tools finally could write the boilerplate, I already knew what good code looked like — because I'd written years of it by hand. I don't use AI as a crutch; I use it as a power tool, and I can tell the difference because I did it the long way first.

    • No autocomplete. Every line typed, every error read and fixed by me.
    • Fundamentals first. Loops, conditionals and functions learned by building.
    • Self-directed. Nobody assigned the projects — I chose them and finished them.
    • It stuck. The debugging instinct from those years is the skill I use most today.

    About

    I'm Luke — a 15-year-old developer from Oklahoma who started writing code in elementary school, years before AI could write it for me. Khan Academy's JavaScript and Processing lessons were my first language; Scratch was where I learned to build games; Unity and Godot came next.

    That early, unassisted practice is the whole reason I can build what I build now. I don't reach for AI to figure out the problem — I reach for it to go faster on a problem I already understand. There's a real difference, and it only comes from having done it the hard way.

    Today I build Minecraft plugins, games and web apps. Math is the through-line: whether it's attack-speed curves, drop rates, or a voice-cloning pipeline, the interesting part is almost always the model underneath. And when I'm not at a keyboard, I'm on the mat.
